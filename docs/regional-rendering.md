# Regional rendering, screensaver and lock-screen fallback

An opt-in rendering experiment can skip expensive scene shading outside a conservative visible region. The normal app retains the established single-window host: the unlocked coverage probe did not produce reliable per-strip AppKit visibility changes, so the four-strip path is disabled by default. Enable it only for development with `--query=regionalRendering=1`. This is deliberately an exact-image optimization: it preserves the current cinematic water, clouds, stars and bloom, rather than changing quality when another app covers the desktop.

## Visibility and rendering

At the validated single-display 1280×800 budget, four opaque vertical wallpaper windows present crops of one shared tone-mapped image. They are click-through, below icons and non-key. They own no independent simulations. AppKit tracks the visibility of the actual presented strips; each strip demands its whole area when any part is visible. An empty transparent-probe prototype was discarded because it did not establish reliable regional evidence in this session; the Mac was subsequently found locked, so that observation is not a general AppKit guarantee. Other budgets, multiple displays and normal app launches retain the original full-window presentation.

The visible tiles form a bounding rectangle. `RegionalRendering.hdrSupport` walks the actual six-level bloom dependency graph backwards, including bilinear neighbours and numerical guards. A single scissor bounds the ocean/sky/stars/rain pass at the validated 1280×800 internal extent. Other internal extents render completely: odd-size scissor experiments changed some water highlights, and fragment-rejection/depth-mask variants did not preserve the original complete image. They were discarded. Geometry is submitted once; FFT waves, foam, reflections, cloud caches and bloom continue as shared work. Regions saving less than 15% of scene shading also retain full rendering to avoid marginal copy overhead. Multiple displays demand the complete shared scene because their aspect-fill mappings can expose different source regions.

A second HDR texture is allocated on first partial render (7.8 MiB at 1280×800). A cheap full-screen copy seeds the MSAA color from the previous HDR image before the scissored scene draw. Hidden pixels therefore retain valid imagery for reveals, rather than turning black. The first frame, full reveals and requested system-wallpaper snapshots render completely. There is no second simulation. A shared 3.9 MiB BGRA display image is tone-mapped once, then byte-exact texture crops are copied only to visible strips. This preserves global dither, rain, vignette and bloom across seams without repeating tone mapping per strip. Each crop includes a one-source-pixel overlap at internal edges; layer contents rectangles exclude that overlap from visible geometry while preserving neighbouring samples during display scaling.

This is intentionally conservative. A narrow visible border on several sides can demand the entire scene once bloom is included. Whole-strip visibility cannot resolve arbitrary pixel-shaped exposure; opposing exposed borders can therefore retain full scene rendering. The fine window-bounds estimate is still used to throttle cadence, but cannot suppress regions the sensors report visible. Fully covered desktops pause, apart from one rare frame for the system still. The original single-window path is the default.

Apple documents the [whole-window visibility semantics](https://developer.apple.com/documentation/appkit/nswindow/occlusionstate-swift.property). This strategy does not require screen capture or a Screen Recording permission.

## Native screensaver

`macos/build.sh` also builds `Ocean.saver` as a Mach-O bundle (not a dylib) and embeds it in Ocean.app. On normal wallpaper launch, Ocean installs or updates that bundled module in the current user's Library/Screen Savers directory and selects it automatically. Users do not need Terminal commands, a separate installer or a manual Settings checklist. Building and headless tests never run setup.

Selection on current macOS uses the WallpaperAgent store, whose private format is also documented by the [PaperSaver project](https://github.com/AerialScreensaver/PaperSaver). Ocean preserves unknown fields, existing Desktop choices and display/Space structure, handles linked wallpaper/saver choices, and saves the complete original file before the first change. It refuses an unknown schema or a conflicting Ocean.saver bundle, checks the store has not changed before writing, reloads only this user's registered WallpaperAgent, and verifies both the new agent identity and every selected module after three seconds. An unchanged failed write is rolled back; concurrent user changes are preserved. This private compatibility layer needs verification on future macOS releases; macOS 13 uses the legacy ScreenSaverDefaults module selection instead. The legacy branch is compiled here but needs a real macOS 13 compatibility check. Unknown newer store formats report setup unavailable without rewriting them.

Later launches update Ocean's module but respect another saver the user deliberately selected. **Repair Screen Saver Setup** retries explicitly. A status line reports the outcome in the Ocean menu. The module URL is encoded without a trailing directory slash and option values use the system's binary-plist representation, so Settings recognizes the same selection that its own chooser writes. The initial supported-store setup and module updates require no admin, Accessibility or Screen Recording permission. The app does not change password requirements or the screen-saver idle delay.

The module uses Apple's [ScreenSaverView lifecycle](https://developer.apple.com/documentation/screensaver/screensaverview) and the same native Metal renderer, shaders and assets. It renders at up to 30 FPS, has a 15 FPS / 320×200 preview budget, reads the app's saved daylight selection and cached IP location/weather from its own ScreenSaverDefaults domain, and makes no network requests. Full-screen displays share one world within a host process; previews use separate small worlds. The desktop app suspends while a saver runs. The app publishes this small environment payload with the system still, so the sandboxed saver host does not need access to the app's cache directory. Missing or invalid preferences use the renderer's local fallback; the saver never asks for location permissions.

Stopping releases presentation views and renderer ownership. Command completion retains and balances the submission semaphore even if the host releases a renderer with work in flight. Shader and galaxy resources are resolved relative to the renderer's bundle, not the screensaver host's main bundle.

## Screensaver efficiency

The saver applies the same pure `PerformancePolicy` as the desktop: 30 FPS on nominal AC power, at most 24 on battery or warm thermals, 15 in Low Power Mode or serious thermal pressure, and 6 under critical pressure. Low Power Mode/serious pressure cap the pixel budget at 75% of balanced; critical pressure caps it at 50%. Policy is sampled every five seconds. A monotonic submission gate enforces the selected cadence even if the host continues invoking its original callback rate. Motion still uses elapsed time.

The wallpaper suspends in response to OS screen-saver, lock, sleep and session events. A Settings preview cannot suspend the desktop: it can keep rendering in Apple's helper after its visible preview closes. An earlier module-heartbeat handoff incorrectly treated that activity as proof that the entire desktop was covered, freezing visible wallpaper. That handoff was removed. Preview cost stays bounded by the small budget and cadence above. Module updates reload cached Apple legacy code only while unlocked and outside the active system saver; otherwise reload is deferred until unlock.

An atmosphere lookup reuse experiment was rejected. Separate process image comparisons initially passed static daytime, midnight, moving sun and changed haze/height, but later produced differences both with and without changed dispatch schedules, including a static scene. That is insufficient evidence for an exact-image optimization. The original lookup scheduling and shader math are retained; no approximation or reduced ray count ships. Investigate deterministic capture/renderer behavior before attempting this optimization again.

The earlier preview heartbeat pause was observed working mechanically, but user testing exposed it as a visible-freeze regression; it is not a retained optimization. No measured battery savings or temperature reduction is claimed. The explicit unlocked opaque coverage probe still reported all four strips visible, so the regional host remains opt-in. Resource timings taken alongside the native saver are not isolated benchmarks.

## System wallpaper / lock screen

A live desktop-level window cannot replace loginwindow's background. Ocean now publishes a complete PNG through Apple's [setDesktopImageURL API](https://developer.apple.com/documentation/appkit/nsworkspace/setdesktopimageurl(_:for:options:)): once after launch, every 15 minutes while the session is active, and after daylight selection changes. A fully hidden desktop renders one offscreen frame for this purpose without acquiring a drawable or activating a window. There is no periodic rendering while locked, sleeping or running a screensaver.

**Update Lock Screen Image** enables/refreshes this synchronization. **Restore Previous Wallpaper and Screen Saver** restores prior desktop URLs and the prior idle choices still owned by Ocean, and disables automatic synchronization until enabled again. Original URLs are saved before changing system preferences. Images use alternating filenames to avoid stale OS image caching. Snapshot conversion/PNG writing runs on a utility queue; OS wallpaper changes happen on the main thread. After the initial saver-selection agent reload, the PNG is reapplied so an asynchronous desktop setter cannot be overwritten by the older store state.

macOS controls how a system wallpaper is used by the lock screen and across Spaces. The snapshot is a still; Ocean does not inject a live view into the authentication UI, change password requirements, modify system assets or replace FileVault's pre-login screen. A selected aerial/screensaver can take precedence over the lock-screen still. Ocean selects its saver during automatic setup to replace that old aerial. Actual lock/unlock behavior must be reviewed interactively; an API success is not proof of the visible lock screen.

## Validation and reproduction

- `zsh macos/test-unit.sh`: geometry/support bounds, odd/narrow sizes, unknown visibility, plus existing contracts.
- `python3 macos/Tests/verify_regional_rendering.py`: GPU comparisons against complete current frames, Metal validation, day/moonlit/storm, four strips/center/moving exposure/full reveal, odd/portrait/ultrawide extents and padded snapshot readback. Requires zero windows/providers. Visible HDR must match exactly; final display must differ by no more than one 8-bit step (observed zero in initial cases).
- `zsh macos/Tests/test-screensaver.sh`: load the native saver bundle, preview lifecycle/restart, shared full-screen resource allocation and stop with work in flight; no windows. Uses real cached environment data, but never performs location/weather requests.
- `python3 macos/Tests/verify_host_scene_parity.py --baseline-app PATH`: complete images against a saved baseline.
- `python3 macos/Tests/benchmark_resources.py --out macos/build/regional/full-resources --scenes noon,storm --frames 240 --extra regionalRendering=0`
- Repeat with `--extra visibleRegion=0,0,0.25,1` and a separate output directory. The synthetic quarter-width strip matches one column of the visibility grid, not every real desktop layout. Keep runs sequential and stop other Ocean processes before benchmarking.

The committed validation report records checks and their scope. Four-strip copies are checked byte-for-byte against the same-frame source so animation/cache timing cannot confound the presentation comparison. Command-buffer GPU time is not whole-device utilization or energy. The extra HDR history, shared display and four presentation windows have memory/compositor costs; neither reduced battery usage nor a 95% saving is claimed.

`macos/Diagnostics/RegionalCoverageProbe.swift` is an explicit 14-second interactive test (`--present` required). It uses one click-through opaque normal-level window ordered behind existing apps to cover the right 75%, then all of the desktop, then reveal it. Requires an unlocked active session; existing apps retain focus. Use Ocean diagnostics to check one-column regional demand, zero-frame pause and recovery. It is never launched by builds, CI, automated regressions or normal startup.

Startup reads the existing session lock state before enabling render callbacks. Unlock/session recovery refreshes the still automatically. Covered-desktop diagnostic benchmarks pass `systemIntegration=0`, so measuring them cannot change wallpapers or screen-saver selection, and reject locked-session results as occlusion evidence. The synthetic astronomy cache round-trip test opts out of file protection only for its temporary fixture; production cache protection is unchanged.
